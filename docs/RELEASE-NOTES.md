# FlipAi v0.46.93

The activity log now says where a browser turn stopped, instead of only that it stopped.

- **Every browser turn reports each stage it reaches.** A turn crosses three processes — the bridge, the provider's worker, and the driver running inside the page — and the only thing that used to survive that trip was one sentence written after the turn had already failed. "It did not work" could equally mean the worker was unreachable, the prompt was never typed, the model never answered, or the answer was found and then discarded. The activity page now carries, under `agent-step`: whether the worker was ready, how long the worker took and what it answered, and the page driver's own account — composer found, prompt typed, sent by button or by Enter, the page accepted it, something that looked like an answer appeared, and how long each took. On a turn that runs out of time it also records what the page looked like at that moment: how many candidate messages there were, whether a stop control was showing, and how much text had been seen. These are metadata — names, timings, counts and lengths. The prompt and the reply are never written to the log.
- **A wrong guess about the page can no longer leave a driver blind.** Deciding which parts of a page are not the conversation — sidebars, headers, tool logs — is guesswork, and a wrong guess meant a driver saw nothing at all: the turn ran its whole budget and reported that the model never answered, while the answer was on screen the whole time. Each of those exclusions is now a preference rather than a rule; if applying it finds nothing, the next pass gives it back.
- **A selector that matches something is not a selector that matches the answer.** When a provider's named elements yield nothing for a turn, Muse and Microsoft Copilot now read the conversation structurally rather than concluding the model never replied.

Validation: publication is gated by the release workflow's full Linux test suite, real-browser call-flow tests, Windows tests, vet, race tests, Windows build, Google Voice integration, installer install/uninstall smoke tests, Microsoft Defender checks, provenance, checksum, and CycloneDX SBOM generation.
