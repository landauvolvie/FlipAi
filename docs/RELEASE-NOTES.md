# FlipAi v0.46.85

ChatGPT Chat answers again, replies read like messages, and a photo reaches a component-built composer.

- **ChatGPT's experience picker was cut off before it finished.** The script that switches between regular Chat and Work retries for over twelve seconds of its own; the generic page-probe deadline is eight. A slow picker was therefore abandoned mid-retry and reported as "the ChatGPT WebView did not answer Runtime.evaluate" — with ChatGPT never seeing the message at all. It now gets a deadline that outlasts it. The same mismatch was found in Claude's Code-mode start, which retries for thirty seconds on the same eight-second allowance, and a new test fails any page script that can outlive its own deadline.
- **Waiting for the browser's control channel no longer spends the waiting call's deadline.** A call could use its whole allowance queueing and then report that the page had not answered, without the page ever being asked. ChatGPT, which issues a burst of small probes around switching experience, failed that way on every message. A call that outlives its deadline also reserves the channel for fifteen seconds now rather than three minutes: a page that navigates, as ChatGPT does, can orphan a call whose callback never arrives.
- **"Copilot said" no longer prefixes the reply.** The speaker label belongs to the page; a text message has one speaker, the agent the sender addressed.
- **A running tool/step log is no longer sent instead of the answer.** Muse shows its steps beside the answer, and the driver was reading whichever text changed most recently anywhere on the page — so a list of timestamped steps went to the phone in place of what Muse actually said. The answer is now anchored to the conversation the prompt landed in, and activity panels are excluded outright.
- **A photo reaches a composer built from web components.** The file-picker finder only looked at the top-level document, so Gemini's picker — inside a shadow root, behind an upload menu — was invisible and the message was refused as "this chat has no file picker". It now searches open shadow roots and recognizes more upload controls.
- Both fixes to the page drivers are verified in a real browser: the driver harness gained a scenario with the tool/step panel that reproduces the mangled reply, and a new harness drives the real file-picker finder against composers that hide their input in a shadow root, behind a menu, or both.

Validation: publication is gated by the release workflow's full Linux test suite, real-browser call-flow tests, Windows tests, vet, race tests, Windows build, Google Voice integration, installer install/uninstall smoke tests, Microsoft Defender checks, provenance, checksum, and CycloneDX SBOM generation.
