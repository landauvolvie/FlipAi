# FlipAi v0.46.94

The new turn trace named both causes on the first log that carried it.

- **ChatGPT was not on a chat page.** Its browser had drifted onto ChatGPT's Scheduled page, which has a box you can type in — "Schedule a task". FlipAi typed the text message into that box, sent it with Enter, and read the page's list of recommended tasks back as the model's answer. That is where "Let me know when a new Dell with Intel, 32 GB RAM, touchscreen, and built-in 5G appears" came from, and why ChatGPT never saw the message. The trace said it outright: `composer-found @0.0s | typed @5.5s | send-enter @5.5s | deadline started=false named=0 blocks=5`. No assistant messages on the page at all, because the page was not a conversation. A turn now requires a conversation before it types anything, returns to one when the browser has drifted, and never accepts a plain text box on a page that is not chat. The trace also records which page the turn ran on.
- **Muse refused turns for ninety seconds while Muse was connected.** A sign-in probe is a guess about someone else's page, and when that guess goes stale the worker is running, the account is signed in, and every turn is still refused with advice to reconnect a connection that was never broken. After twenty seconds, a worker that is alive and answering its own health check now runs the turn, and the page driver reports what it actually found. This applies to all six browser agents.
- **A readiness failure now says what was missing** — the worker was not running, the worker was not answering, or the page reported itself signed out — rather than one sentence that covers all three.
- The driver harness grew to thirty-eight scenarios. The new one serves the provider's own site at a page that is not a chat, and fails if a driver types the message into it. It fails against the previous driver with exactly this release's bug.

Validation: publication is gated by the release workflow's full Linux test suite, real-browser call-flow tests, Windows tests, vet, race tests, Windows build, Google Voice integration, installer install/uninstall smoke tests, Microsoft Defender checks, provenance, checksum, and CycloneDX SBOM generation.
