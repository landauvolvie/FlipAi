# FlipAi v0.46.86

ChatGPT Chat, and replies that carry only the message.

- **ChatGPT's page driver had no fallback of any kind.** It looked for exactly one attribute, in the top-level document, with no shadow-root search, no structural fallback and no Enter key. When ChatGPT's page did not match, the turn produced nothing, sat out its ninety-second checkpoint and reported that the model had stopped without answering — while the answer was on screen. It now has the same robustness as the other drivers: open shadow roots, a structural fallback anchored to the conversation the prompt landed in, and Enter when no Send control can be named.
- **A navigation was being reported as a failure.** Every provider ran `location.href = …` as a page call and treated a missing answer as an error — but navigating destroys the execution context that call is running in, so it frequently never answers. That is the navigation working. An `O:` message came back as "could not open regular ChatGPT Chat: the WebView did not answer Runtime.evaluate" without ChatGPT ever seeing it. Whether the navigation worked is now decided by the readiness wait that already followed it, in all six providers.
- **A status line is no longer sent as the answer.** "Searching sources" sat unchanged long enough to look settled and went to the phone in place of what the model said. A short status is never accepted as final; the drivers keep waiting for the answer.
- **The reply's action row is no longer part of the message.** "Edit in a page", "Copy", "Good response" and the rest are controls for the person looking at the browser. They are stripped from the page text, and again from the reply itself — where a one-word control such as "Copy" only counts as furniture if the page set it apart, so an answer ending in "you can copy" keeps its last word.
- The driver harness now covers ChatGPT as well as Copilot and Muse, and gained two scenarios taken from what actually went wrong: a page that shows an interim status before answering, and a reply with an action row under it. Both reproduce the reported text exactly before the fix.

Known: switching ChatGPT Work mode can still refuse with "FlipAi could not verify ChatGPT Work mode". That check fails closed on purpose, so a task is never sent into the wrong experience, and it was left alone rather than loosened blind.

Validation: publication is gated by the release workflow's full Linux test suite, real-browser call-flow tests, Windows tests, vet, race tests, Windows build, Google Voice integration, installer install/uninstall smoke tests, Microsoft Defender checks, provenance, checksum, and CycloneDX SBOM generation.
